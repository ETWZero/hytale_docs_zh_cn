在这份设计描述以及由此产生的状态机中，处理玩家实际上分为两部分。我们有一个初始的 **Alerted** 状态，然后是战斗本身。现在，我们先从实现所有感知检查以及 **Alerted** 状态开始，它充当通往战斗行为本身的过渡状态。

首先，我们先在 **CallRat** 状态之后创建一个空的 **Alerted** 状态，并带有一个将其送回 **Idle** 的超时。在我们通过感知检查为其添加引用之前，模板会停止编译，但这没关系。

```json
{
  "Sensor": {
    "Type": "State",
    "State": "Alerted"
  },
  "Instructions": [
    {
      "Reference": "Component_Instruction_State_Timeout",
      "Modify": {
        "_ExportStates": ["Idle"],
        "Delay": [10, 15]
      }
    }
  ]
}
```

有许多不错的组件可用于处理感知检查。这里我们将使用一个方便的 Sensor 组件：**Component_Sensor_Standard_Detection**。为了让它生效，我们会设置一个态度组（**Goblin**），该组很可能也会被所有其他哥布林共用，并引用一个已有的 **Goblin NPC group**。我们可以根据态度检测不同的 NPC，并做出相应的反应。

```json
{
  "Groups": {
    "Friendly": ["Goblin"],
    "Hostile": []
  }
}
```

目前我们实际上没在里面放多少内容，因为还没有实现多少其他相关的 NPC；但等有了之后，我们可以把任何敌对者添加为敌对。我们会在参数中引用它，并将其分配给食人魔的态度组，同时添加一个对玩家的默认态度（并默认忽略大多数 NPC）。我并不真的期待会有「友好」的食人魔，所以现在就不麻烦把默认玩家态度做成参数了。

```json
"Parameters": {
	...
    "AttitudeGroup": {
        "Value": "Empty",
        "Description": "This NPCs attitude group"
    },
	...
},
...
"DefaultPlayerAttitude": "Hostile",
"DefaultNPCAttitude": "Ignore",
"AttitudeGroup": { "Compute": "AttitudeGroup" }

```

为了在食人魔身上配置「视觉」和「听觉」，我们还需要再添加几个与此相关的参数。

```json
"Parameters": {
	...
    "ViewRange": {
        "Value": 15,
        "Description": "View range in blocks"
    },
    "ViewSector": {
        "Value": 180,
        "Description": "View sector in degrees"
    },
    "HearingRange": {
        "Value": 8,
        "Description": "Hearing range in blocks"
    },
    "AlertedRange": {
        "Value": 30,
        "Description": "A range within which the player can be seen/sensed when the NPC is alerted to their presence"
    },
    "AbsoluteDetectionRange": {
        "Value": 4,
        "Description": "The range at which a target is guaranteed to be detected. If zero, absolute detection will be disabled."
    },
	...
}

```

这些参数相当不言自明，但 **ViewRange/ViewSector** 控制食人魔能看多远以及他的视野锥，**HearingRange** 控制他的听觉范围能延伸多远，而 **AlertedRange** 控制的是：当食人魔察觉到目标的存在后，目标可以走多远而仍处于被追踪状态。**AbsoluteDetectionRange** 允许我们设置一个距离，在该距离内食人魔一定会对我们做出反应，而不论任何其他条件。

这个 Sensor 还有几个其他参数，例如我们也可以显式地将某些 NPC 组排除在检测之外！但就我们的目的而言，一个简单的 Attitude 过滤器就足够了。

我们花点时间讲讲它是如何工作的。这个传感器有不同的检查：

- 首先检查**绝对检测范围**内是否有东西，如果没有任何东西满足过滤器，则继续进一步检查。
- 然后**检查 ViewRange/Sector 内是否存在潜在目标**。如果有目标位于视野锥和范围内，并且到它的视线畅通无阻，那我们就能「看到」它。
- 如果 NPC 什么都看不到，它会**尝试「听」**。这一点更具体一些——如果目标在行走或奔跑且没有蹲下，我们就能「听到」它，而不受大多数其他因素的影响（不过它不会「隔墙听到」）。这让它相当敏锐，因此我们倾向于给它设置比视野范围低得多的检测半径。

```json
{
    "$Comment": "Check for any hostile targets in range that could alert the NPC",
    "Sensor": {
        "Reference": "Component_Sensor_Standard_Detection",
        "Modify": {
            "ViewRange": { "Compute": "ViewRange" },
            "ViewSector": { "Compute": "ViewSector" },
            "HearingRange": { "Compute": "HearingRange" },
            "ThroughWalls": false,
            "AbsoluteDetectionRange": { "Compute": "AbsoluteDetectionRange" },
            "Attitudes": ["Hostile"]
        }
    },
	"Actions": [
		{
			"Type": "State",
			"State": "Alerted"
		}
	]
},
{
	"Sensor": {
		"Type": "State",
		"State:" ".Default"
	},
...

```

此时，模板会重新编译，我们可以在游戏内观察到，以各种方式接近食人魔都会让它切换到 **Alerted** 状态。

![npc tutorial 5](/assets/official-documentation/npc/npc-tutorial-5.jpg)

我们也想把该组件添加到其他空闲状态，例如睡觉和进食，但在这两种情况下，我们可能都想稍微降低它们的检测能力。让我们添加某种系数作为参数。

```json
"Parameters": {
	...
    "DistractedPenalty": {
        "Value": 2,
        "Description": "A factor by which view range and hearing range will be divided when this NPC is distracted"
    },
	...
}

```

然后，我们会为 **CallRat** 状态使用之前的配置，但为 **Sleep** 和 **Eat** 状态使用修改后的版本。在接下来的片段中只展示了 **Sleep** 状态，但其他状态应按需照做。我们通常把这些检查紧跟在仅触发 **Once** 和 **Continue** 的指令之后（这些基本上是初始化指令）。

```json
{
  "Sensor": {
    "Type": "State",
    "State": "Sleep"
  },
  "Instructions": [
    {
      "$Comment": "Check for any hostile targets in range that could alert the NPC",
      "Sensor": {
        "Reference": "Component_Sensor_Standard_Detection",
        "Modify": {
          "ViewRange": { "Compute": "ViewRange / DistractedPenalty" },
          "ViewSector": { "Compute": "ViewSector" },
          "HearingRange": { "Compute": "ViewRange / DistractedPenalty" },
          "ThroughWalls": false,
          "AbsoluteDetectionRange": { "Compute": "AbsoluteDetectionRange" },
          "Attitudes": ["Hostile"]
        }
      },
      "Actions": [
        {
          "Type": "State",
          "State": "Alerted"
        }
      ]
    }
  ]
}
```

在这里我们可以看到之前未使用过的一项功能——计算值实际上包含了一次计算：我们将 **ViewRange** 和 **HearingRange** 除以 **DistractedPenalty**，从而得到受限的检测半径。

现在，无论处于什么状态，食人魔都能对任何威胁做出反应！接下来我们会稍微充实 **Alerted** 状态，让它真正完成所需的职责。让我们回顾一下那是什么：

- 如果坐着就站起来（这一点已由状态转换处理）
- 咆哮，命令附近的哥布林拾荒者发起攻击
- 开始缓慢走向玩家进行攻击（我们会把这部分视为战斗）

那样的话，我们在这里需要做的就是让食人魔看向它的目标、播放咆哮动画（也许还有一些粒子），并发出信标以警告附近的哥布林拾荒者。首先我们需要一个简短的 **NPC 组**（**Goblin_Scrapper**）来定义哥布林拾荒者，这样我们就能把信标专门发送给它们。

```json
{
  "IncludeRoles": ["Goblin_Scrapper"]
}
```

我们也会添加一个引用它的参数。

```json
"Parameters": {
	...
    "WarnGroups": {
        "Value": ["Goblin_Scrapper"],
        "Description": "The groups to warn when spotting an enemy"
    }
	...
}

```

然后实现 **Alerted** 状态的基础部分，最后过渡到用于战斗的 **Combat** 状态。

```json
{
	"Sensor": {
		"Type": "State",
		"State": "Alerted"
	},
	"Instructions": [
		{
			"Reference": "Component_Instruction_Play_Animation",
			"Modify": {
				"Animation": "Alerted"
			}
		},
		{
			"Continue": true,
			"Sensor": {
				"Type": "Target",
				"Range": { "Compute": "AlertedRange" },
				"Filters": [
					{
						"Type": "LineOfSight"
					}
				]
			},
			"HeadMotion": {
				"Type": "Watch"
			}
		},
		{
			"Sensor": {
				"Type": "Target",
				"Range": { "Compute": "AlertedRange" }
			},
			"ActionsBlocking": true,
			"Actions": [
				{
					"Type": "Timeout",
					"Delay": [1, 1]
				},
				{
					"Type": "State",
					"State": "Combat"
				}
			]
		},
		{
			"Actions": [
				{
					"Type": "State",
					"State": "Idle"
				}
			]
		}
	]
},
{
	"Sensor": {
		"Type": "State",
		"State": "Combat"
	},
	"Instructions": []
}
```

这里涉及不少逻辑，但相当直接。我们播放一个动画，然后只要到目标的视线畅通，就持续注视目标。接着在切换到 **Combat** 状态前有一个很短的延迟。我们会通过状态转换来实际把信标消息发送给其他哥布林（同时清除动画）。

```json
{
  "States": [
    {
      "From": [],
      "To": ["Combat"]
    }
  ],
  "Actions": [
    {
      "Type": "PlayAnimation",
      "Slot": "Status"
    },
    {
      "Type": "Beacon",
      "Message": "Goblin_Ogre_Warn",
      "TargetGroups": { "Compute": "WarnGroups" },
      "SendTargetSlot": "LockedTarget"
    }
  ]
}
```

在我们进入 **Combat** 状态中真正的战斗行为之前，还有一类感知检查需要实现：**伤害**。如果玩家可以躲在某处狙击我们的食人魔而他毫无反应，那就不行了。

使用 `Component_Instruction_Damage_Check` 组件可以非常轻松地做到这一点，该组件旨在评估 NPC 是否受到了伤害并做出相应反应。如果目标已知且距离合理，它会切换到战斗的 **Chase** 状态，否则会切换到 **Panic** 状态。我们的食人魔相当强悍，而且肩负重要任务，所以我们实际上不会让他恐慌——如果他受到伤害，他只会切换到 **Alerted** 以警告附近的其他个体，然后冲上去砸碎威胁！

尽管示例中只展示了一个实例，但我们会把它放在每一处放置视觉/声音检查的地方，并通过放在最前面来赋予它更高的优先级。

```json
{
    "Reference": "Component_Instruction_Damage_Check",
    "Modify": {
        "_ExportStates": ["Alerted", "Alerted"],
        "AlertedRange": { "Compute": "AlertedRange" }
    }
},
{
	"$Comment": "Check for any hostile targets in range that could alert the NPC",
    "Sensor": {
		...
```

完成这些后，我们的食人魔就应该能对我们需要的所有情况做出反应了！现在我们可以专注于让它真正攻击它的目标了！
