# 自定义 UI

## 什么是自定义 UI？

自定义 UI 是 Hytale 用于创建由游戏服务器控制的**自定义用户界面**的框架。与内建的客户端 UI（属于游戏客户端的一部分，无法修改）不同，服务器 UI 允许你通过 Java 插件和资源包创建可交互的界面与 HUD 覆盖层。

作为模组作者，自定义 UI 赋予你以下能力：

- **创建自定义交互页面** - 商店界面、任务对话框、服务器设置菜单、管理员面板
- **添加自定义 HUD 覆盖层** - 任务追踪器、状态显示、自定义生命值条、服务器信息
- **使用标记语法设计** - 使用 `.ui` 文件定义可复用的 UI 模板
- **处理用户交互** - 响应按钮点击、表单提交和其他事件
- **本地化你的 UI** - 使用游戏的翻译系统支持多种语言

## 自定义 UI 如何融入 Hytale 的 UI

Hytale 的用户界面分为两大类：

### 客户端 UI（无法模组化）

由 C# 游戏客户端控制的内建界面：

- 主菜单和设置
- 角色创建
- 内建 HUD（生命值、快捷栏、聊天）
- 物品栏和合成界面
- 开发工具

**这些界面无法修改** - 它们是核心游戏客户端的一部分。

### 游戏内 UI（可通过服务器模组化）

你可以创建并自定义的、由服务器控制的界面：

#### 自定义页面

在游戏过程中出现的全屏交互覆盖层：

- 可由玩家关闭（ESC 键）
- 捕获所有输入（键盘和鼠标）
- 支持在等待服务器响应时显示加载状态
- 适用场景：商店、对话框、菜单、配置界面

#### 自定义 HUD

绘制在游戏世界之上的常驻覆盖元素：

- 仅用于显示（无用户交互）
- 在游戏过程中始终可见
- 轻量且不干扰操作
- 适用场景：任务目标、状态指示器、服务器信息面板

## 架构概览

服务器 UI 使用**基于命令的架构**：

```
┌─────────────────────┐         ┌──────────────────────┐
│   Java Server       │         │    C# Client         │
│   (Your Plugin)     │         │    (Game)            │
├─────────────────────┤         ├──────────────────────┤
│                     │         │                      │
│ InteractiveCustomUI │         │   CustomPage or      │
│ Page                │         │   CustomHud          │
│   ↓ build()         ├────────→│     ↓ Apply          │
│ UICommandBuilder    │         │   Element Tree       │
│   - append()        │         │     ↓ Layout         │
│   - set()           │         │   Rendered UI        │
│   - clear()         │         │                      │
│                     │         │                      │
│ ↓ handleDataEvent() │← Events │   User Interaction   │
│   Process input     │         │   (click, type, etc) │
│   sendUpdate()      │         │                      │
└─────────────────────┘         └──────────────────────┘
```

**流程：**

1. 你的 Java 代码使用 `UICommandBuilder` 构建 UI
2. 命令以数据形式发送到客户端
3. 客户端解析 `.ui` 标记文件并创建可视元素
4. 用户与 UI 交互
5. 事件被发回你的 Java 代码
6. 你处理事件并发送更新回去

## 核心原则

### 声明式而非命令式

你不直接创建 UI 对象，而是发送描述你想要什么的**命令**：

- “将此按钮模板追加到那个容器”
- “将该标签的文本设为 'Hello World'”
- “清空此列表的所有子元素”

### 资源驱动

UI 结构定义在 `.ui` 标记文件（资源）中，而非硬编码在 Java 里。这带来了：

- 设计师无需接触代码即可修改布局
- 可复用的 UI 组件
- 一致的视觉语言

### 事件驱动

用户交互会触发事件，事件流回你的服务器代码。你注册事件绑定，并在 `handleDataEvent()` 中处理它们。

### 基于选择器

你使用**选择器**定位特定的 UI 元素：

- `#MyButton` - ID 为 “MyButton” 的元素
- `#List[0]` - 元素 “List” 的第一个子元素
- `#List[0] #Title` - 元素 “List” 的第一个子元素中 ID 为 “Title” 的元素
- `#Label.TextColor` - 元素 “Label” 的 TextColor 属性
